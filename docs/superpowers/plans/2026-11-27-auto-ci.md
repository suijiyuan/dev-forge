# Auto CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run complete CI against the commit Auto pushes to master before tagging and releasing it.

**Architecture:** Expose the existing CI as a reusable workflow with an optional ref input. Split Auto into update, ci, tag, and release jobs, passing the exact update SHA through validation and tagging.

**Tech Stack:** GitHub Actions YAML, Bash, existing Python unittest suite.

**Spec:** `docs/superpowers/specs/2026-11-27-auto-ci-design.md` (approved).

## Global Constraints

- Keep Linux Python 3.10–3.13 and Windows PowerShell checks.
- Keep master push and PR CI triggers and default event commit selection.
- Keep 08:00 Asia/Shanghai scheduling, GITHUB_TOKEN, and existing bot identity.
- No updates or dry_run: no new full CI, tags, or Release.
- CI failure: retain the pushed master commit, skip tagging and publishing.
- Release and CI must use the exact update commit even if master advances.
- Keep release.yml unchanged; do not push or trigger a live release during local validation.

## Review Focus

- PR CI must keep testing the merge commit when no ref is supplied.
- No-change and dry_run must skip all downstream jobs.
- A failed CI job must block tagging and Release.
- Later master commits must not change the release target.
- Existing date-based tag sequencing must continue from fetched remote tags.

**Interfaces:** CI accepts optional string `ref`. Auto update outputs `changed`, `sha`, `target_version`; tag outputs `tag`. Release consumes the tag output.
